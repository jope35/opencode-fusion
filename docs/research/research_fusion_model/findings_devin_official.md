# Findings: Devin "Fusion" — official/primary sources (subtopic `devin_official`)

Research date: 2026-10-30. Linear issue WHE-29. All sources below are official (Cognition blog, docs.devin.ai) and were read in full via direct URL fetches. Note: the `exa` and `jina` search tools returned empty/null results in this environment, so discovery was done via https://docs.devin.ai/llms.txt (docs index) and cross-links inside the pages; no web search results were used.

## TL;DR

"Fusion" is **not a single merged/ensemble model**. It is a **multi-model agent harness**: two parallel agents — a frontier **lead** and a cheaper **sidekick** — each with its own persistent, cached context and toolset, plus **dynamic mid-session model switching** driven by lightweight classifiers at context-compaction boundaries. The lead is always in charge (plan, ambiguity, final review); the sidekick executes mechanical work. There is **no voting, averaging, distillation, or output-merging** described anywhere — combination happens by **delegation + lead review + mid-session routing/switching**, and writes stay single-threaded.

## 1. What "fusion" is and when/how it activates

- Docs (Desktop + CLI, identical text): "Fusion pairs a frontier lead model with a cost-efficient sidekick, delivering frontier intelligence at a lower cost." Fusion is a **selectable model option**, not an always-on system: "Open the model selector in a Devin Local session — from the composer, or by running `/model` — and pick Fusion." In the CLI, `/fusion` opens the Fusion picker (`/fusion` is CLI-only, not in Desktop). "You interact with a single Devin; the pairing happens behind the scenes."
  - Sources: "Fusion in Devin Desktop" https://docs.devin.ai/desktop/fusion ; "Fusion in Devin CLI" https://docs.devin.ai/cli/fusion
- Availability (docs): "Fusion is available on paid plans in Devin CLI **3000.10.20+** and Devin Desktop **3.10.0+**. It's not included in free or trial tiers." Warning: "not available for customers on legacy or credit-based plans."
- Cloud: the announcement blog (2026-06-29) says "We'd love for you to try Devin Fusion in preview at app.devin.ai/signup … release a preview of Devin Fusion to users in our cloud agent." Release notes 2026 show Fusion in the **web app model picker**: 2026-07-24 — "The model picker has been redesigned into a single organized menu where you can choose a capability, **toggle Fusion**, adjust speed, and switch modes"; 2026-08-12 — the Automations/On-Call agent mode selector shows 'the resolved organization default (e.g. "Org default (Fusion)")'. Desktop changelog v3.6.21 (2026-07-29): session-create cards show a Devin mode badge "Fast, Ultra, Fusion". The local-fusion blog (2026-09-11): "We have seen great results with Fusion on Devin Cloud over the past few months, and we are excited to bring it to your machine."
  - Sources: "Devin Fusion: Frontier Performance at 60% Lower Cost" https://cognition.com/blog/devin-fusion (2026-06-29); "2026 release notes" https://docs.devin.ai/release-notes/2026 (entries of 2026-07-24 and 2026-08-12); "Devin Desktop changelog" https://docs.devin.ai/desktop/changelog (v3.6.21, v3.10.23, v3.10.27, v3.10.48); "Introducing Fusion in Devin Desktop & CLI" https://cognition.com/blog/local-fusion (2026-09-11)
- Ship dates in changelogs: Devin CLI **v3000.10.21 (2026-09-10)** and Devin Desktop **v3.10.23 (2026-09-10)** both carry a banner "Introducing Fusion in Devin Desktop and Devin CLI" linking to cognition.com/blog/local-fusion. Desktop **v3.10.27 (2026-09-15)**: "Devin Fusion can be activated even when Claude Fable 5.1 isn't available as a lead model." Desktop **v3.10.48 (2026-09-29)**: "for the best value, use Fusion with **GPT-6 Astra as the lead and SWE-2 as the sidekick**."
  - Source: "Changelog (Stable)" https://docs.devin.ai/cli/changelog/stable ; "Devin Desktop changelog" https://docs.devin.ai/desktop/changelog

## 2. Inputs

- Standard Devin session inputs: user prompt, repo/file context (AGENTS.md auto-loaded on setup per release notes 2026-10-09; indexed repo, @-mentions, Knowledge, skills/rules), conversation history. The docs do not list any special Fusion-specific inputs.
- Internally, per the announcement blog, the two agents are "fully capable agents with their own toolsets and ability to gather & act on their own context"; "both the main model and sidekick model maintain their own persistent, cached contexts." The lead and sidekick exchange only "briefs, results, and feedback" — "the sidekick doesn't need the lead's entire history … and the lead doesn't need every intermediate tool result."
- The blog explicitly notes prompts alone are insufficient for routing: "Prompts often do not contain enough information about the task to properly discern difficulty" — hence mid-session routing (see §3).
  - Sources: https://cognition.com/blog/devin-fusion ; https://cognition.com/blog/local-fusion

## 3. Pipeline steps (in order, as described)

1. User selects **Fusion** and configures a pairing: **Lead** (frontier model), **Effort** (lead reasoning compute), **Sidekick** (cost-efficient executor; each lead shows a recommended sidekick), optional **Fast Mode** (faster variants of the same models, "same intelligence, higher speed, at a higher cost"). Docs recommend **Fable 5.1 + SWE-2**; the local-fusion blog recommends **Opus 5.5 + GPT-6 Luna** (pairing recommendations evolved over time).
2. The **lead** owns the session: "it plans, reasons through the hard parts, and reviews the work"; "the plan, the interpretation of ambiguity, the final review." It "should take minimal actions, and only read what is absolutely necessary. By default it should delegate and monitor."
3. The **sidekick** runs as a **parallel agent** with its own tools/context: "executes the lead's plan — writing code, running builds and tests, and verifying changes." The lead "hands the sidekick a brief of each task it delegates, with constraints and success criteria"; the sidekick "explores code, implements changes, runs tests, and reports back."
4. The lead **reviews** the sidekick's work: "The lead always reviews the work, identifies problems, and can take control back when the sidekick is out of its depth."
5. **Dynamic mid-session routing**: "we use lightweight classifiers during task execution to signal when we need to switch to the main agent or use a different model entirely." Model switches are performed **during context compaction** (which would cause a cache miss anyway): "Each time we trigger compaction, we take it as an opportunity to evaluate the situation and switch the model that's in charge, effectively getting model switching 'for free'… we can even 'upgrade' our sidekick model without going back to the main model, at no extra cache penalty." (Caveat noted by authors: "most cached inputs only have a 5-minute expiry.")
6. From the user's perspective the output is a **single Devin session**; per the multi-agent engineering post, multi-agent setups at Cognition work best when "writes stay single-threaded" and extra agents "contribute intelligence rather than actions."

Sources: https://docs.devin.ai/desktop/fusion ; https://docs.devin.ai/cli/fusion ; https://cognition.com/blog/devin-fusion ; https://cognition.com/blog/local-fusion ; https://cognition.com/blog/multi-agents-working (Walden Yan, 2026-04-22)

## 4. Mechanism combining outputs — what docs say vs. imply

- **What is explicitly stated**: delegation with lead review + mid-session model switching via classifiers at compaction boundaries. Quote: "The Fusion architecture ensures that frontier intelligence is always in charge. We don't assign tasks to a cheaper model hoping that the routing decision was correct. The lead always reviews the work, identifies problems, and can take control back." (local-fusion blog)
- **What is NOT present**: no ensemble/averaging, no voting, no distillation into one model, no edit/merge step combining two models' outputs. The only "combination" is: sidekick's artifacts (code, test runs) land in the shared session/workspace and are accepted/reworked by the lead; the session's active model can be swapped mid-session. The user "interact[s] with a single Devin."
- Related but distinct: **Adaptive** is a separate per-request **model router** ("Adaptive is Cognition's intelligent model router that automatically selects the best AI model for each task… Devin evaluates each request and dynamically chooses the right underlying model"). Docs explicitly steer users from Adaptive to Fusion ("For most users we recommend Fusion"). Fusion's routing is mid-session/within-task; Adaptive routes per request. The local-fusion blog argues pure routing is insufficient: "the initial prompt isn't enough to know the difficulty of the task… you break prompt caches by switching models mid-task."
- Predecessor pattern documented in "Multi-Agents: What's Actually Working" (2026-04-22): the "Smart Friend"/Advisor pattern (one model calls another as a tool) was tried and rejected for Fusion because "upon every call to the other model, the context for the task is not shared in a way that is cached, and you pay a very expensive price." Fusion instead gives each agent its own cached context.

Sources: https://cognition.com/blog/devin-fusion ; https://cognition.com/blog/local-fusion ; https://docs.devin.ai/cli/adaptive ; https://docs.devin.ai/desktop/adaptive ; https://cognition.com/blog/multi-agents-working

## 5. Which models are involved

- Fusion = a **family of lead+sidekick pairings**, user-configurable. Named pairings in official material: **Fable 5.1 + SWE-2** (docs' recommended pairing), **Opus 5.5 + GPT-6 Luna** (local-fusion blog, 2026-09-11), **GPT-6 Astra + SWE-2** (Desktop changelog v3.10.48 recommendation for ChatGPT-plan users), **Astra + SWE-2** and **Fable 5.1 + SWE-2** (benchmark table).
- Lead candidates: frontier models — Anthropic "Fable 5 / 5.1" (access suspended 2026-06-12 per a US government directive, per footnote in the devin-fusion blog), "Opus 5 / 5.5", OpenAI "GPT-6 Astra / Luna / Sol", etc. Sidekick candidates: cost-efficient models — Cognition's in-house **SWE-2** (Medium/High/Max effort; list $3.00/1M in, $15.00/1M out), **GPT-6 Luna**, GPT-5.6, etc.
- Model landscape (docs "AI Models"/"Models" pages): Devin supports latest models from Anthropic, OpenAI, Google, Cognition "within minutes of their launch" plus open-source (DeepSeek, Kimi, GLM). In-house family: SWE-2, SWE-1.7 (+Lightning on Cerebras), SWE-1.6 (+Fast), SWE-1-mini, swe-grep, swe-check.
- Benchmark-comparison models named in the fusion blog chart: Fable 5 (xhigh), Opus 5 (medium), GPT-5.6 Sol (high), Kimi K3, Grok 4.5 (high).

Sources: https://docs.devin.ai/desktop/fusion ; https://docs.devin.ai/cli/fusion ; https://cognition.com/blog/devin-fusion ; https://cognition.com/blog/local-fusion ; https://docs.devin.ai/desktop/models ; https://docs.devin.ai/cli/models ; https://docs.devin.ai/desktop/changelog

## 6. Published benchmarks / claims, with dates

- **2026-06-08** — "Introducing FrontierCode" (https://cognition.com/blog/frontier-code): Cognition's own benchmark (150 tasks Extended / 100 Main / 50 Diamond, built by 36 OSS maintainers, >40h/task; measures "mergeability" — correctness + quality; ensemble grading: unit tests, rubrics, verifiers; 81% lower false-positive rate vs SWE-Bench Pro). This is the eval Fusion is measured on, not a Fusion claim itself.
- **2026-06-29** — "Devin Fusion: Frontier Performance at 60% Lower Cost" (https://cognition.com/blog/devin-fusion, by The Cognition Team): on **FrontierCode 1.1 Extended**: Fable 5 (xhigh) 64.9 @ $10.53; Opus 5 (medium) 63.6 @ $3.51; **Devin Fusion 63.1 @ $3.41**; GPT-5.6 Sol (high) 58.7 @ $3.12; Kimi K3 58.2 @ $1.09; Grok 4.5 (high) 56.6. Claim: "maintains frontier and Fable 5-level performance at 60% lower cost" — footnote: "We initially reported a 35% cost reduction at publication. On the latest FrontierCode 1.1 Extended data (**updated 8/7/2026**), Fusion is up to 60% cheaper." Also: "Fusion with Fable 5 is **41% cheaper** than a pure Fable 5 harness, versus up to 60% with Opus and GPT-5.5-level models." Internal sanity check: "**88% of their merged PRs were driven entirely by the automated Fusion router**" (internal Cognition users). Worked examples with per-task cost deltas (e.g., −62%, −32%, −38%, −28%, −25% cost with score changes +2 to −27, showing delegation can hurt on judgment-heavy tasks).
- **2026-09-11** — "Introducing Fusion in Devin Desktop & CLI" (https://cognition.com/blog/local-fusion): "Fusion is the most efficient frontier harness for Opus, Fable and Astra, up to **39% more efficient** compared to other model harnesses across major coding benchmarks." Artificial Analysis Coding Agent Index v1.5 (chart updated **10/19/2026**): Devin Fusion Opus 5.5 + GPT-6 Luna = 68.1 @ $8.1 → **31% lower cost** than Claude Code Opus 5.5 (100 @ $13.04); Devin Fusion Astra + SWE-2 = 58.9 @ $4.54 → **39% lower cost** than Codex Astra (100 @ $7.47). Benchmark table (score @ avg cost): DeepSWE 1.1: Fable 5.1 64.3/$14.63 → Fusion (Fable 5.1+SWE-2) 63.1/$7.88 (−46%); Astra 67.6/$7.88 → 67.3/$4.69 (−40%). Terminal-Bench 4.0: 57.6/$17.46 → 56.1/$13.37 (−23%); 55.6/$10.08 → 50.0/$6.06 (−40%). SWE-Atlas QnA: 64.8/$7.57 → 65.9/$5.00 (−34%); 61.8/$5.72 → 59.4/$3.59 (−37%). Vals Code Migration: 54.6/$70.97 → 57.3/$42.00 (−41%); 67.7/$44.36 → 61.3/$35.51 (−20%). FrontierCode 1.1 Extended: 63.6/$2.68 → 63.5/$1.67 (−38%); 63.1/$2.62 → 63.4/$2.34 (−11%). Also: "using more expensive models can make the entire system cheaper" — Fable 5 as lead made sessions 9% cheaper than Opus 4.8 lead at same sidekick; SWE-2 sidekick vs GPT-5.6 Luna sidekick under Astra lead: 63.4 @ $2.34 vs 62.0 @ $2.39.
- Pricing/billing claims (docs): "Fusion bills each model in the pairing at its own rate: the lead at its frontier rate and the sidekick at its lower rate." Self-serve: per-token quota drawdown at each model's rate. Enterprise: metered in **ACUs** scaling with both models' tokens. CLI `/session-stats` shows "token usage, cost by model, and estimated Fusion savings."

## 7. Things NOT confirmable from the pages read (flags)

- No official page describes the **internals of the "lightweight classifiers"** used for mid-session routing (only that they exist and run "during task execution"); no details on training, features, or thresholds.
- No official page states whether lead and sidekick share the same workspace/files or separate sandboxes; it is implied they share the session's workspace (sidekick writes code the lead reviews), and the CLI changelog mentions "a running Fusion sidekick" being excepted from interrupt-parking — but the exact context-sync format ("briefs") is only described qualitatively.
- The docs' recommended pairing (Fable 5.1 + SWE-2) differs from the 2026-09-11 blog's (Opus 5.5 + GPT-6 Luna); Fable 5.1 access was suspended 2026-06-12 (per the blog footnote), and Desktop v3.10.27 (2026-09-15) notes Fusion can be activated without Fable 5.1 as lead. Which pairing is default today is not stated.
- A dedicated **docs page for Fusion in Devin Cloud** was not found in the docs index (llms.txt lists fusion pages only under Desktop and CLI); cloud availability is evidenced by the blog preview announcement, release notes (2026-07-24 model-picker toggle; 2026-08-12 org default "(Fusion)" in Automations/On-Call), and the 2026-09-11 blog ("great results with Fusion on Devin Cloud").
- No evidence anywhere of output-level combination (voting/averaging/merging/distillation). If asked "how are outputs combined": answer per official sources = they aren't merged; the lead reviews/accepts/rejects sidekick work and can take over; the active model can switch mid-session.
- The exact date of the cloud Fusion preview rollout beyond "preview at app.devin.ai/signup" (2026-06-29 blog) is not stated.
- Search-tool caveat: exa/jina search returned no results in this environment; all sources were reached via docs.devin.ai/llms.txt and in-page links.
