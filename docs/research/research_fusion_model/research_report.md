# Research report: How the Devin "fusion" model works (inputs, steps, output combination)

Linear issue WHE-29. As-of date: 2026-10-30. Audit trail: `research_plan.md`, `findings_devin_official.md`, `findings_copilot_fusion.md`, `findings_independent.md`. Grilling questions live in the separate file `grilling_questions.md` (per the issue).

## Answer

"Fusion" is **not a single merged or distilled model**. In both Devin (Cognition) and GitHub Copilot, it is a **runtime orchestration layer on top of existing closed models** — a router plus, in some paths, a judge or parallel critics. **Inputs** are the normal session inputs (prompt, conversation, repo/workspace context) plus routing signals (task capability signals, effort level, cache boundaries, real-time model health, plan/policy constraints); Devin adds a second fully-capable agent with its own cached context. **Steps** are: classify/route the task → execute with one model or a draft→review/escalate sequence → present only the final result. **How outputs are combined**: they are *not* merged token-by-token. Devin Fusion combines by **delegation + lead review** (the lead accepts, reworks, or takes back the sidekick's work; the active model can switch mid-session at compaction boundaries). Copilot Fusion combines by **selection or critique-and-revise**: Single = one model's output wins; Cascade = a judge accepts the draft or escalates (no merge); Critique = several models' feedback is aggregated and the *drafting model itself* revises — the only "merge" is done by an LLM reading the critiques. No vendor source describes voting, averaging, ensembling, or distillation of outputs, and no independent source found evidence of distillation either (unsettled, since both vendors are closed-source).

## Findings

### 1. Devin Fusion (Cognition) — official sources

- **What it is / activation.** A selectable "Fusion" option in the model picker (Desktop 3.10.0+, CLI 3000.10.20+, paid plans; cloud preview announced 2026-06-29; web-app picker toggle in release notes 2026-07-24). "Fusion pairs a frontier lead model with a cost-efficient sidekick." You "interact with a single Devin; the pairing happens behind the scenes." [docs.devin.ai/desktop/fusion](https://docs.devin.ai/desktop/fusion); [docs.devin.ai/cli/fusion](https://docs.devin.ai/cli/fusion); [cognition.com/blog/devin-fusion](https://cognition.com/blog/devin-fusion) (2026-06-29)
- **Inputs.** Standard session inputs (prompt, indexed repo, @-mentions, history). Internally each agent keeps "their own persistent, cached contexts"; lead and sidekick exchange only "briefs, results, and feedback." Cognition notes prompts alone don't reveal task difficulty, hence mid-session routing. [cognition.com/blog/devin-fusion](https://cognition.com/blog/devin-fusion); [cognition.com/blog/local-fusion](https://cognition.com/blog/local-fusion) (2026-09-11)
- **Steps.** (1) User picks a lead+sidekick pairing (docs recommend Fable 5.1 + SWE-2; later blog/changelog recommend Opus 5.5 + GPT-6 Luna, or GPT-6 Astra + SWE-2). (2) The **lead** plans, handles ambiguity, reviews; it "should take minimal actions… delegate and monitor." (3) The **sidekick** runs as a parallel agent with its own tools/context: explores, implements, runs tests, reports back against the lead's brief. (4) The lead reviews and "can take control back when the sidekick is out of its depth." (5) **Dynamic mid-session routing**: "lightweight classifiers during task execution" signal model switches, executed at context-compaction boundaries because "compaction triggers a cache miss anyway… effectively getting model switching 'for free'" (caveat: cached inputs often have a 5-minute expiry). (6) Writes stay single-threaded; the user sees one Devin session. [docs](https://docs.devin.ai/desktop/fusion); [cognition.com/blog/devin-fusion](https://cognition.com/blog/devin-fusion); [cognition.com/blog/local-fusion](https://cognition.com/blog/local-fusion); [cognition.com/blog/multi-agents-working](https://cognition.com/blog/multi-agents-working) (2026-04-22)
- **Output combination.** Explicitly: delegation + lead review + mid-session switching. Quote: "The Fusion architecture ensures that frontier intelligence is always in charge… The lead always reviews the work, identifies problems, and can take control back." **No** ensemble/averaging, voting, distillation, or edit-merge is described anywhere. Distinct from "Adaptive," a separate per-request router. [cognition.com/blog/local-fusion](https://cognition.com/blog/local-fusion); [docs.devin.ai/cli/adaptive](https://docs.devin.ai/cli/adaptive)
- **Benchmarks/claims (vendor).** FrontierCode 1.1 Extended (vendor-built eval; data updated 2026-08-07): Fusion 63.1 @ $3.41 vs Fable 5 xhigh 64.9 @ $10.53 — "up to 60% lower cost"; "41% cheaper than pure Fable 5 harness"; "88% of internal merged PRs fully router-driven." 2026-09-11 post: "up to 39% more efficient"; AA Coding Agent Index chart (updated 2026-10-19): Fusion Opus 5.5+GPT-6 Luna 68.1 @ $8.10 (−31% vs Claude Code Opus 5.5); Fusion Astra+SWE-2 58.9 @ $4.54 (−39%). Per-benchmark table shows cost cuts of 11–46% with occasional score regressions (e.g., Terminal-Bench 4.0 Astra-led 50.0 vs 55.6 solo). [cognition.com/blog/devin-fusion](https://cognition.com/blog/devin-fusion); [cognition.com/blog/local-fusion](https://cognition.com/blog/local-fusion)
- **Billing.** Each model in the pairing bills at its own rate; CLI `/session-stats` shows cost by model and estimated Fusion savings. [docs.devin.ai/desktop/fusion](https://docs.devin.ai/desktop/fusion)

### 2. GitHub Copilot Fusion — official sources

- **What it is / activation.** Docs: "Copilot Fusion is an intelligent runtime model router and orchestrator. It chooses models and execution patterns for your task, then returns a single response." GA 2026-10-28 (GitHub Universe) in VS Code, Copilot CLI, Copilot app, JetBrains, all plans; evolved from research preview Project HydraFusion (2026-09-04) + Auto model selection. GitHub CPO: "It's not a model. It's an orchestration engine at runtime" (VentureBeat, 2026-10-28). [docs.github.com/en/copilot/concepts/models/copilot-fusion](https://docs.github.com/en/copilot/concepts/models/copilot-fusion); [github.blog/changelog 2026-10-28](https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion/); [github.blog HydraFusion 2026-09-04](https://github.blog/ai-and-ml/github-copilot/project-hydrafusion-frontier-quality-via-multi-model-orchestration/)
- **Inputs.** Prompt + conversation; capability signals (reasoning, code generation, debugging, tool use); chosen effort level (Standard/High/Max; Fusion Fast = inline chat only); real-time model health/availability; cache/conversation signals ("routing occurs along natural cache boundaries"); workspace context (solver steps run in the shared workspace; review/critique steps in isolated, tool-less contexts); plan/admin policies. Fusion has no context window of its own — each step uses the running model's limits. [GitHub docs](https://docs.github.com/en/copilot/concepts/models/copilot-fusion); [HydraFusion blog](https://github.blog/ai-and-ml/github-copilot/project-hydrafusion-frontier-quality-via-multi-model-orchestration/)
- **Steps (per prompt).** (1) Lightweight pattern selection. (2) Execute one of three patterns: **Single** — one model completes the task; **Cascade** — efficient model drafts, a judge accepts or escalates to a stronger model (2026-10-14 update adds a repair-only-when-needed judging step); **Critique** — one model drafts while multiple models critique in parallel, feedback is aggregated, and the original model revises. (3) Model + reasoning effort set per step (medium drafts, high review). (4) Only the final response is shown; users can watch per-step progress/models and hover the effort label to see which models ran. Engineering principles: complete cost accounting per leg, bounded execution, isolated review, fail-safe application, validated routing; routing policies tuned offline (beam search on CheckpointBench/DeepSWE/TerminalBench 2.1). [docs](https://docs.github.com/en/copilot/concepts/models/copilot-fusion); [changelog 2026-10-14](https://github.blog/changelog/2026-10-14-hydrafusion-updates-and-new-max-option/); [HydraFusion blog](https://github.blog/ai-and-ml/github-copilot/project-hydrafusion-frontier-quality-via-multi-model-orchestration/)
- **Output combination.** Router + orchestrator; **no token-level ensembling, voting, or weight-averaging**. Single = pure selection. Cascade = judge-gated selection (accept draft or escalate; no merge of the two outputs). Critique = the aggregation is done **inside the drafting model**, which revises from combined feedback; the aggregation mechanism itself is unspecified. [docs](https://docs.github.com/en/copilot/concepts/models/copilot-fusion)
- **Models.** Pool deliberately unpublished and changing; 2026-10-14 changelog names Claude Opus 5.5, GPT-6 Astra, GPT-6.1 Sol, GPT-6 Luna; Artificial Analysis observed Sonnet 5.5 and GPT-6 Sol too; local MAI Code 1.1 Flash / Qwen3.8 Flash Next possible at Fusion Standard. [changelog 2026-10-14](https://github.blog/changelog/2026-10-14-hydrafusion-updates-and-new-max-option/); [VentureBeat 2026-10-28](https://venturebeat.com/orchestration/github-copilot-fusion-mixes-models-to-achieve-near-opus-5-5-coding-performance-at-half-the-per-task-cost)
- **Benchmarks/claims.** HydraFusion offline evals (2026-09-04): TerminalBench 2.1 +4.9 pts at 67% lower cost vs Opus 5; DeepSWE −1.5 pts at 36% lower cost. GA claim (2026-10-28): AA Coding Agent Index — Fusion Max **60** vs ~62 for Claude Code + Opus 5.5 Max at ~half the cost; AA v2.0 detail via VentureBeat: **$5.59 vs $11.42/task (−51%)**, 7.2M tokens/task (~half), Terminal-Bench 4.0 71 (led), FrontierCode 51 (behind). "~40% less time" and "up to 77% savings" (DeepSWE) are company-reported, not independently published. [changelog 2026-10-28](https://github.blog/changelog/2026-10-28-route-and-orchestrate-models-with-github-copilot-fusion/); [VentureBeat 2026-10-28](https://venturebeat.com/orchestration/github-copilot-fusion-mixes-models-to-achieve-near-opus-5-5-coding-performance-at-half-the-per-task-cost)
- **Billing.** Billed per model used at standard rates, no separate Fusion charge; paid plans get a 30% model-cost discount through 2026-11-30. [docs](https://docs.github.com/en/copilot/concepts/models/copilot-fusion)

### 3. Independent / third-party evidence

- **Mechanism classification matches the academic taxonomy** (arXiv:2603.04445 routing/cascading survey; arXiv:2502.18036 LLM-ensemble survey; JAIR 2026 arXiv:2502.00409): Devin Fusion = **two-agent lead+sidekick harness with dynamic mid-session routing** (router/delegation family); Copilot Fusion = **router + three patterns, Critique closest to an ensemble** but merged by the drafting model. Neither is a learned merge at the token level; no evidence of distillation. [arXiv:2603.04445](https://arxiv.org/abs/2603.04445); [arXiv:2502.18036](https://arxiv.org/abs/2502.18036); Artificial Analysis LinkedIn 2026-09-11; [The Batch 2026-09-25](https://www.deeplearning.ai/the-batch/one-agent-works-another-directs)
- **Independently supported claims.** AA Index v1.5: Devin Fusion Fable 5.1(xhigh)+SWE-2 scored ~62 vs 62.2 for Fable 5.1 max in Claude Code at **−36% cost** ($7.90 vs $12.40/task), but with **70% more tokens and ~3× the turns** (The Batch). AA v2.0: Copilot Fusion Max 60 vs 62 at −51% cost (vendor-funded eval, published by independent lab). Cascades can genuinely cut cost (FrugalGPT, arXiv:2305.05176), but require in-distribution labeled data and add scorer cost. [AA LinkedIn 2026-09-11](https://www.linkedin.com/posts/artificial-analysis_we-independently-benchmarked-devin-fusion-activity-7504270671208665088-AuFO); [The Batch](https://www.deeplearning.ai/the-batch/one-agent-works-another-directs); [VentureBeat 2026-10-28](https://venturebeat.com/orchestration/github-copilot-fusion-mixes-models-to-achieve-near-opus-5-5-coding-performance-at-half-the-per-task-cost); [arXiv:2305.05176](https://arxiv.org/abs/2305.05176)
- **Marketing-only / unverifiable.** Cognition's "60% lower cost" (vendor-built FrontierCode; number drifted 60%→39% as data updated); "88% of merged PRs router-driven" (internal dogfood); GitHub's "77% savings" and "40% less time" (company-reported, raw data unpublished). [eesel.ai 2026-07-02](https://www.eesel.ai/de/blog/devin-fusion-test); [VentureBeat](https://venturebeat.com/orchestration/github-copilot-fusion-mixes-models-to-achieve-near-opus-5-5-coding-performance-at-half-the-per-task-cost); [Data Studios 2026-10-29](https://www.datastudios.org/post/github-copilot-fusion-generally-available-automatic-model-routing-all-plans)
- **Contradicted or qualified.** Component-level regressions exist (Astra-led Fusion: Terminal-Bench −5.6 pts, Vals migration −6.4 pts; Woofun reported swings +12/−27 and net cost increases at high parallel-panel invocation rates — snippet-only, lower confidence). The literature contests that mixing models helps: Self-MoA (arXiv:2502.00674) shows mixing different LLMs "often lowers" quality; debate can converge to confidently wrong consensus (arXiv:2604.07667: 23.9% of disputed items → unanimous wrong). [alphasignal.ai 2026-09](https://alphasignal.ai/news/cognition-s-fusion-cuts-devin-coding-agent-costs-by-46-with-two-model-teamwork); [arXiv:2502.00674](https://arxiv.org/abs/2502.00674); [arXiv:2604.07667](https://arxiv.org/html/2604.07667); [woofun.ai 2026-08-17](https://www.woofun.ai/en/news/detail/104734) [flag: snippet only]
- **Community reimplementations** of Devin's sidekick pattern (pi-extensions pi-fusion; mihneaptu/opencode-fusion) confirm it is a reproducible harness pattern, with measured per-turn delegation overhead (~316 extra input tokens/turn) and savings only on tasks with bulky tool output. [github.com/luongnv89/pi-extensions](https://github.com/luongnv89/pi-extensions/blob/main/extensions/pi-fusion/README.md); [github.com/mihneaptu/opencode-fusion](https://github.com/mihneaptu/opencode-fusion)

## Conflicts and gaps

- **Savings magnitude disagrees across sources**: measured −36% to −51% (AA) vs vendor-claimed up to −60%/−77%; Cognition's own figure drifted 60%→39% as its eval data updated. Treat the AA-measured range as the most trustworthy; budget against per-benchmark tables, not headlines.
- **Quality parity is not uniform**: composites near-tie while components regress by up to ~6 pts (and Woofun claims −27 worst case, low confidence).
- **"Does mixing models help?" is unresolved in general** — task-dependent; vendor "two models is the sweet spot" (Guyman) vs Self-MoA's contrary finding.
- **Docs vs changelog discrepancies** in Copilot's Cascade/Critique internals (judge semantics, number of critics).
- **Unsettled / unconfirmable**: whether anything is distilled into one model (closed-source vendors; absence of evidence ≠ evidence of absence); Copilot's full model pool (unpublished); the internals of Devin's "lightweight classifiers"; the Critique aggregation mechanism; whether lead and sidekick share one workspace or sandboxes; whether Copilot Fusion is offered in cloud agent/GitHub.com chat; the 77% and 40%-less-time figures (no raw data). Also: exa/jina search MCPs were rate-limited in this environment, so discovery leaned on one search provider plus direct fetches — possible gaps in non-English coverage.
